# work-personal-secretary（集成体本体）

> **定位**：工作秘书集成体的**本体插件**。一个集成体、一个设置入口；五个子插件各自独立。
> 本体的**第一大功能是安装器**（环境检查 → 依赖补齐 → 子插件安装 → 配置底座），
> **第二大功能**是把 DSH 底层配置（指令层 / 记忆种子 / 技能 / 设置）在安装时分步落地。

## 这个模块做什么

| 能力 | 状态 |
|---|---|
| 设置左侧独立分区「**工作秘书**」 | ✅ 本版提供 |
| **安装与检查**（环境检查 / 依赖补齐 / 子插件安装 / 配置底座） | ✅ 本版提供 |
| **核心配置**（首次配置引导：目录与岗位 → 保存即执行一次生成） | ✅ 本版提供 |
| **配置**（把五个子插件的设置集中到本分区读写；原「能力配置」） | ✅ 本版提供 |
| **随包说明网页**（安装引导页 / 使用说明页，设置页内可展开） | ✅ 本版提供 |
| **关于与致谢**（集成体版本 · 五个子插件 · 第三方来源 · 免责边界） | ✅ 本版提供 |

## 为什么是独立分区，而不是宿主「插件配置」页

DSH 的**设置 → 插件 → 插件配置**页只列**宿主平面插件**（终端 / Agent 循环 / Subagent / 网页搜索）。
用户插件要出现在其中，需自行贡献 `settings.plugin.item`。本集成体选择注册独立的
`settings.section` 分区：既不会与宿主插件混淆，也比在插件列表里翻找直观。

## 安装

```bash
dsh plugin --profile <profile> add <本模块目录>
```

宿主侧改动需**重启 DSH** 才加载；仅客户端改动刷新页面即可（客户端 bundle 按 revision 缓存，
故每次改动都会升 `package.json` 的版本号，界面里的 `BUILD` 常量与它同步维护）。

## 目录结构

```text
work-personal-secretary/
├── package.json          # dsh.bundle.patch 指向 cordis.patch.yml；dsh.client.inject 声明客户端包
├── cordis.patch.yml      # 中性部署默认层（不含个人路径/称呼）
├── lib/index.js          # 宿主半入口：子插件清单 + 版本读取 + 路由接线（零运行时依赖）
├── lib/probe.js          # 七项只读环境探针
├── lib/install.js        # 子插件安装引擎（原子替换 + 逐文件 SHA256 校验）
├── lib/basedeck.js       # 配置底座引擎：指令层 / 记忆种子 / 技能 / 设置 / 目录 + 两个结构生成器
├── lib/preflight.js      # 可用性检查（环境就绪 / 目录合法可写 / 同工作区 / 目标无冲突）
├── lib/identity.js       # 「使用者身份」条目写入（区间替换 + 目录锁 + 备份 + 逐字节校验 + 回滚）
├── lib/domain.js         # 五个预置岗位正文 + 生成通道（promptEnhancer → llm 降级）
├── lib/md.js             # Markdown → HTML（随包说明网页渲染；转义 + 链接白名单）
├── lib/settings.js       # 本体设置命名空间
├── lib/settings-api.js   # 配置页宿主侧：设置只读枚举 / 白名单写入 / 专家打分预览
├── client/index.js       # 客户端半：手写 loader bundle，注册 settings.section 分区
├── defaults/             # 随包单一真相源：install.zh-CN.md（安装引导）· use.zh-CN.md（使用说明）
├── scripts/              # 七套自测脚本（不依赖宿主运行时）
├── CHANGELOG.md
├── NOTICE                # 集成体包含的子插件与第三方致谢
├── LICENSE
└── README.md
```

**不引入构建步骤**：客户端半是手写的 `window.__ModuleLoader__.load({ id, factory })` bundle，
只依赖宿主注入的 `react`；与集成体现有模块（`dsh-work-memory`）写法一致。

## 配置项

`cordis.patch.yml` 是**中性部署默认层**，提供以下可选项；个性化可在该 profile 的 `cordis.patch.yml`
或设置页用户层按 id 覆盖：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `selfCheckOnStartup` | `false` | 启动时做一次只读环境探测并在日志里给出结论 |
| `repoRoot` | `''` | 集成体仓库目录（子插件安装的来源）。**留空 = 自动探测**集成体仓库目录；也可在此显式指定 |

## 默认约定

首装即生效的两条，写在随包指令模板 `defaults/AGENTS.zh-CN.md` 与记忆种子 `defaults/global-memory.seed.md` 里（两者都在**本模块的 `defaults/` 内**，与使用/安装说明同处，随包分发），可由使用者改写：

1. **语言**：回答与推理使用**简体中文**；代码、命令、路径、包名、API/字段名、日志与报错原文等保留英文原样，不刻意翻译。
2. **协作**：主对话负责拆解、派单、核对与对外沟通，具体工作交专家子代理执行；涉密或敏感内容由主上下文直接处理。

两条的完整正文在指令模板（DSH 每轮作为指令注入，约束力强于记忆层）；记忆层只放兜底指针，避免两处措辞漂移。

## 设计约定

- **中性**：发布件不含任何个人身份、称呼、私有路径或记忆数据；
- **零运行时依赖**：宿主 peer 缺失时不影响加载；
- **不写死版本**：宿主半从自身 `package.json` 读取版本；子插件版本由后续的安装器探测（不在界面里写死）；
- **设置分层**：`cordis.patch.yml` 是部署默认层，个性化只走设置页用户层；
- **安装安全**：子插件以**原子替换**就位（临时目录 → 逐文件 SHA256 校验 → 替换，旧目录保留到最后）；
  装前备份 profile 的 `package.json`（写后校验 JSON 与 BOM），备份只保留最近 **10** 份，失败自动回滚。
