## 一、命令与脚本

1. **`dsh plugin --profile <profile> <参数…>` 的本质是「在 profile 目录里把参数转发给 pnpm」** 【官方】——`dsh plugin --help` 输出的就是 pnpm 自己的帮助。
2. **装完立刻校验：`dsh --profile <profile> --dump-config`** 【官方】——不启动即可检查组合后的配置树；能看到 `- id: <插件 id>` 才算注册成功。
3. **一次性任务用 headless**：`dsh --profile headless "<任务>"` 跑完打印结果即退出 【官方】。
4. **快速起 Web UI**：`npx @deepseek-ai/dsh web`，默认 `http://127.0.0.1:3080`，本机启动时会用默认浏览器打开；`--no-open` 只跑服务器 【官方】。
5. **只有 `dsh` profile 能启动受支持的 Node 应用**；包的 bin、demo 与「用 SDK argv 逃逸」都被禁止 【官方】。⚠️ 版本敏感
6. 技能脚本路径**不要写死**：用占位符 `<DOC_SUITE_SCRIPTS>`，实际路径由 `py -3 doctor.py --emit-skill-paths` 输出（读 JSON 的 `scriptsDir`）【约定】。
7. 排障开关：`DOC_SUITE_DEBUG=1` 打印完整堆栈（默认只给中文单行错误 + `exit 2`）【约定】。
8. 拉不动某个仓库源码时，可改用 GitHub 的 tarball 接口下整仓，再解压 【实测】。
9. **打包用 `npm.cmd pack`**（Windows 上绕开 PowerShell 的脚本执行策略；直接 `npm` 可能被策略拦住）【实测】。

## 二、设置项

10. **官方硬约定：凡是「不同部署可能取不同值」的参数，都必须定义为配置字段** 【官方】——这与我们「可调数值不进指令层」的做法同源。
11. **配置变更会触发插件热替换** 【官方】——改配置通常不必重启。⚠️ 版本敏感
12. 媒体/生图设置是**扁平顶层键**（如 `mediaImageEnabled` / `mediaArkApiKey`），并声明 `applies: 'live'` 免重启 【约定】；嵌套键在「能力配置页」读不到也写不进。
13. 专家库的 `identityExpert` **留空＝身份专家不常驻**（身份由记忆层承担）【约定】。
14. 记忆库设置里**唯一需要重启**的是「摘要顺序」，其余即时生效 【约定】。
15. 可调数值（TTL 天数、注入条数上限、专家阈值、告警条数）**只放设置页、不写进指令层** 【约定】——写死会与设置页打架并随版本漂移。
16. **设置入口与生效方式对照** 【约定】：

| 想改什么 | 去哪里 | 生效方式 |
|---|---|---|
| 存储根、工作岗位 | 设置 → 工作秘书 → 核心配置 | 点「保存配置并开始」后按六步执行 |
| 记忆库（目录、注入条数、转冷周期、备份份数） | 设置 → 工作秘书 → 配置 → 记忆库 | 即时（只有「摘要顺序」要重启） |
| 专家库（开关、岗位域、注入篇幅） | 设置 → 工作秘书 → 配置 → 专家库 | 即时 |
| 文档能力自检 | 设置 → 工作秘书 → 配置 → 文档能力 | 点一次即检查 |
| 宠物大小 / 动画 / 语言 / 形象 | 设置 → 小宠物设置，或宠物面板「设置」页签 | 即时 |
| 子插件安装与升级、环境检查 | 设置 → 工作秘书 → 安装与检查 | 装完可能需要重启 |

## 三、安装与升级

17. **配置树叠加顺序**：各 bundle 的 patch → profile 的 `cordis.patch.yml` → `$DSH_HOME/cordis.patch.yml` → `--patch` 参数 【实测】⚠️ 版本敏感——排查「我改的怎么没生效」先看这个顺序。
18. **patch 会替换目标行的整个 `config`，不是合并** 【实测】⚠️ 版本敏感——少写一个键就会丢默认值。
19. `patchReload: live` 会监视 profile 与 home 级 patch；`startup` 只应用一次 【实测】⚠️ 版本敏感。
20. **bundle 解析顺序**：先 dsh 安装目录（内置 base/web/headless/sdk 等），再 profile 自身的 `node_modules` 【实测】⚠️ 版本敏感。
21. **装进 profile 的必须是「真实副本」，不能是 junction/符号链接** 【实测】——否则 Node 沿真实路径向上解析，找不到 `@deepseek-ai/*` 运行时包。
22. `desktop` 这个 profile 名**保留给 Electron**，CLI 会拒绝针对它的启动、`--dump-config` 与插件管理请求 【实测】⚠️ 版本敏感（本机 0.1.5 口径）。
23. 桌面 app 有 **install-recovery 事务**：处于 awaiting-restart 时，手改 `package.json` 会被回写还原 【实测】。
24. **bundle 是启动时加载，不能热切换**：装、删、更新 profile 插件都要重启 【官方】。
25. 客户端 bundle 按 **revision** 缓存：改了 `client/` 必须同步升 `package.json` 的 version，否则重启也看不到变化 【实测】。
26. **profile 目录结构**：`package.json`（含 `dependencies` 与有序的 `dsh.profile.bundles`）+ `cordis.patch.yml`（用户 patch 层）【官方】。
27. **装回 / 升级四步** 【实测】：① 把**真实副本**（不是链接）放进 profile 的 `node_modules/<包名>`；② 在 profile 的 `package.json` 里加 `file:` 依赖并写进 `dsh.profile.bundles`；③ 执行插件安装命令；④ **重启**。中途任何一步跳了都会出现「装了但没生效」。

## 四、排障与恢复

28. 报 `Cannot find package '@deepseek-ai/<x>'` → 插件被装成了链接，改真实副本 【实测】。
29. pnpm store v10/v11 不一致 → 用 `link:` 本地包绕过 store，或先 `pnpm install` 迁移 【实测】。
30. WPS COM 的 `SaveAs` **不认相对路径**（报错误码 3011）→ 一律传绝对路径 【实测】。
31. WPS COM 导出**同名**文件会返回上一次的缓存画面 → 出图必须换文件名或换目录，否则会误判「改了没生效」【实测】。
32. WPS COM 用完会残留 `wpp`/`wps` 进程：按**启动时间**甄别清理，**绝不盲杀使用者正开着的 WPS** 【实测】。
33. **「命令成功返回却什么都没发生」→ 先怀疑进程窗口状态**（`windowsHide` / `detached` / `stdio`），而不是命令与参数 【实测】。
34. `windowsHide: true` 会让 `explorer /select` **静默失效**（退出码还被容错逻辑吞掉）【实测】。
35. PowerShell 写 JSON 会带 **BOM** → 一律用 Python/Node 写（解析器会直接拒绝带 BOM 的 JSON）【实测】。
36. PowerShell 会**吃掉空参数**（例如把 `-N ''` 变成 `-N -q`）→ 用 Node 的 `spawnSync` 传 argv 【实测】。
37. **绝不用 PowerShell 的 `ConvertTo-Json` 发 GraphQL**：它会把字符串当字符数组展开（3 KB 正文膨胀成 4 MB），而表层报错却是「基础连接已关闭」——用 Python 构造 JSON 【实测】。
38. **UTC 日界坑**：`toISOString()` 会让本地清晨写入的数据落到「昨天」【实测】。
39. 文本文件写入纪律：**UTF-8 无 BOM** + 原子替换 + 先备份 + 只替换目标区间 【实测】。
40. Python 写文本用 `write_bytes(text.encode('utf-8'))`，**不用 `write_text`**（Windows 上会转成 CRLF）【实测】。
41. **代理（官方专篇）**：DSH 只认**标准代理环境变量**（`HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY`），**不读取操作系统的代理设置**；**始终绕过 loopback**（不必列 `127.0.0.1`）；**它替你运行的 `git`、`gh` 等子进程继承同一代理**；**不支持 SOCKS**；也可写 `$DSH_HOME/.env`（默认 `~/.dsh/.env`）【官方】——这条同时解释了「系统代理开着、命令行却连不上」。⚠️ 版本敏感

## 五、记忆与检索

42. 全文检索默认**遵循 `.gitignore`**：要搜被忽略的目录（如工作区里的记忆目录），加 `--no-ignore` 【实测】。
43. **转冷基准日 = max(写入日, 最后使用日)**；TTL 天内（含第 TTL 天）仍算热 【约定】。
44. **「被用到」只算**：检索命中、建立关联、冷转热写回；**每轮注入、面板浏览、巡检与保养都不算** 【约定】——否则 TTL 永不生效。
45. **快照有上限**：总字符 4000（超出截断），分段条数＝全局 20 / 偏好 12 / 项目 16 / 日志 8 【约定】（源码默认值）——所以重要内容要短、要精简。
46. **全局记忆超过约定条数（默认 20 条）会触发整理提醒**，看到就当场整理，不要等别人发现 【约定】。
47. 分类口诀：**「换个项目还成立吗？」**成立→全局或偏好；不成立→项目（默认落点）；当天流水→日志 【约定】。
48. 涉密或敏感内容标 `tag=敏感`：不自动注入，只在显式检索时返回 【约定】。
49. 若配置了外部知识库镜像：**镜像目录当只读参考**，改动走工具或面板，避免下次同步被覆盖 【约定】。
50. **转冷预审三态** 【约定】：**自动保留**（与近期日志/全局记忆相关、含未完结或决策约定措辞、图谱有关联、被反复用过 → 顺延一个 TTL）· **自然转冷**（含完成/一次性信号、已被更新条目取代）· **待判断队列**（信号不足）。待判断条目由助手在保养时**逐条判定**，只有助手也拿不准的才交使用者；超 7 天宽限自动转冷。**判定只写判定文件，不删、不改任何条目**。
51. **整理记忆的手法** 【约定】：按 id **精确搬移**（不改写原文）· 搬前**先备份** · 搬后同步镜像并记日志。
52. **记忆库七条命令** 【约定】：`/memory_review`（看待确认的关键记忆）· `/memory_archive`（立刻归档）· `/memory_backup`（立刻备份）· `/memory_audit`（分类巡检）· `/memory_maintain`（周保养）· `/memory_promote`（把归档条目取回热区）· `/memory_triage`（转冷预审）。

## 六、插件机制

53. 工具注册用官方 DSL：`defineTool({ name, description, parameters, output, isConcurrencySafe, execute })`；`parameters` 的属性内写 **`required: true`**（不是 JSON Schema 的 `properties/required` 数组）；`output` 走 `{ schema, render }` 两段 【官方】。
54. 工具呈现有 `mode`：`native` / `ptc` / `both`（默认 `native`）；PTC 模式下模型只看到 `run_code` 与生成的 SDK 【官方】。⚠️ 版本敏感
55. `ctx.tools.restrict(filter)` 按 agent 收窄工具集（多个取交集）；`guard()` 注册**单调守卫**（拒绝后不可被后续监听器翻回）【官方】。
56. **web-server 路由匹配顺序固定**：先查 exact 表 → 再取**最长匹配 prefix** → 最后落到已注册的回退；**`prefix` 是一等合法路由**（`exact` / `prefix` 两种 kind）【官方】。⚠️ 版本敏感
57. web-server：同一路径**重复注册会抛错**；`registerFallback` 只能有一个所有者，第二次注册也抛错；没有 fallback 时返回 404 【官方】。
58. web-server 的 `host` 只接受 `127.0.0.1`（默认）与 `0.0.0.0`（**后者不带 TLS、认证与来源策略**）；`port: 0` 由操作系统分配，可从 `ctx.webServer.port` 读回 【官方】。
59. **桌面（Electron）经 `file://` 加载已构建文件、用 IPC 桥接发送 fetch 请求，不使用 web-server** 【官方】；因此「桌面壳只认 exact 路由、prefix 返回 404」是**那层 IPC 桥的实测行为**，不是官方设计 【实测】。
60. 客户端资源：失败要用 `{ ok:false, error }` 帧而不是抛错；一个协议**恰有一个提供方**，二次注册抛错 【官方】。
61. Word 里中文字体必须**显式设 `eastAsia`**（只设 `font.name` 时中文会回落到默认东亚字体）【实测】。

## 七、编辑器与界面

62. **跨重启继续同一会话会残留旧的 system 节点**（体积可观）→ 想要干净上下文就**开新会话** 【实测】。
63. GUI 里出现两块「系统提示词」不是渲染 bug，是「新版追加、旧版留历史」的 in-history 行为 【实测】。
64. 桌面 app 的编译产物在 `resources/app*` 下：**改本机产物会在下次升级被覆盖**——这类问题应作为产品侧议题反馈，而不是改本机 【实测】。
65. 桌宠**没有关闭开关、也没有透明度调节**，只能收起统计面板 【约定】。

## 八、方法与纪律

66. **假插件三步判据**：① 全库检索该包有无 import（只在文档/注释里出现＝代码零引用）② `pip show` 看 `Required-by` 是否为空 ③ 它的「名义用途」是否真的成立；三条全中即假插件 【实测】。
67. **自测脚本三规约**：不读本机私有状态（`~/.dsh/**` 与工作区真实文件）· 不写固定路径（用 `mkdtemp` 一次性目录）· 自己造的自己清（`finally` / `exit` 兜底）【实测】——这正是「本机全绿 ≠ CI 全绿」的根因。
68. **提交前做干净环境验证**：把本机私有文件临时移开再跑一遍 【实测】。
69. Windows 专属语义（盘符、大小写、跨盘）的断言在 Linux runner 上**必须加平台守卫** 【实测】。
70. **只验证函数不验证端到端会漏**：改完必须端到端复验一次 【实测】。
71. **对外提交（发帖、评论、提交 PR）属对外动作**，需使用者明确授权后再执行；查询类可随时跑 【约定】。
72. **数字与条款纪律**：**数字要么实测、要么查原文**，否则不写；拿不准的标「以某某原文为准」，不臆断 【约定】。
