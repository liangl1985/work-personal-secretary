# 本机写入包 · 怎么用

> 你看到的这个**开局**文件夹，是新装机器上还没完成"本机写入"时留下的**内容包**。
> 它里面装的东西，本该由安装器写到你电脑上的几个位置。**这个包就是那些内容的原件。**

## 为什么会有这个文件夹

安装器有时找不到该写入的位置（例如换了一台机器、目录还没建、或某个源文件读不到）。
与其**悄悄跳过**、让你以为一切正常，不如把内容**原样放在这里**，并明确告诉你：**还有几件事没做完**。

只要这个包还在、且提醒还没消失，就说明本机写入**没有全部完成**。

## 里面有什么，各自该写到哪

| 这个包里的 | 应该写到哪 |
|---|---|
| `后置优化包/AGENTS.md` | 你的**工作区根目录**下的 `AGENTS.md`（只替换带标记的那一段，你自己写的部分不动） |
| `记忆库/` | 你的**记忆库目录**（`MEMORY.md`、`USER.md`、`GRAPH.json`、`PROJECTS/工作秘书.md`、`PROJECTS`/`DAILY`/`ARCHIVE` 三个目录） |
| `知识库/` | 你的**知识库目录**（`🏠 主页.md`、`00_全局记忆/`、`工具/` 与三个子目录、`工具/00_工具总览.md`、`工具/技能/DSH与插件使用技巧.md`） |
| `技能/` | 你的**工作区**下的 `.dsh/skills/`（五个技能） |

`后置优化包/清单.json` 是给程序看的**核查清单**：每一项都写明「源文件 → 目标位置 → 比对方式」。
目标位置用的是 `{{workspace}}`、`{{memoryDir}}`、`{{obsidianDir}}` 这类**占位符**，由你机器上的实际配置解析 —— 所以同一个包在任何机器上都成立。

## 怎么执行（两种办法，任选一种）

**办法一：走设置页（推荐，最省事）**
1. 打开 DSH 设置 → **工作秘书 → 核心配置**；
2. 把「存储根目录」和「知识库目录」填成你实际想用的位置；
3. 点**保存配置并开始**，让配置链自己跑一遍。

**办法二：让助手按清单写**
对助手说一句「**按 `开局/后置优化包/清单.json` 逐项写入**」即可。
助手会按清单逐项比对，该写的写、该报的报。

## 怎么算完成

清单里每一项有三种结果：

- **缺失** → 从包里写过去；
- **一致** → 通过；
- **不一样** → **不覆盖**，只报告差异（因为可能是你自己改过的），由你决定保留哪一份。

**全部通过**之后：记忆库里的那条提醒会被摘掉，并留一行完成记录。这个包**不删**，留着便于回溯。

## 有几点先说清楚

- **只补缺失，不覆盖你的东西**：记忆库和知识库里属于你的内容（日记、笔记、业务资料）一律不动；比对只针对**上面表格里列的那几个文件/那几段**。
- **写不进去会如实说**：某个源文件读不到、或目标目录不可写，会**明确写成原因**并保留提醒，不会假装成功。
- **这个包不是备份**：它是"还没写进去的内容原件"。写入完成后，你的实际使用位置以上表右侧为准，不用管这个包。
