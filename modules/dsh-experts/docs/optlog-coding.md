交付：• 交付物：分级审查结论（阻塞 / 建议 / 小改）；逐条问题与修改建议（带行号与原因）；可合并性判断与验证方式；发布前自检结果。  • 交付前自检（逐条过）：① 每条阻塞都指到具体行并给了可执行修法；② 事实与意见分开标注；③ 没把风格偏好当阻塞；④ 关键路径测试与失败路径都看过。
适用：审查代码改动、做发布前自检、评估合并与回退风险时

**共性发现（供其他域参考）**
1. **L1 卡的真正约束是"方法 1-3 的前 60 字"**——第 4 条之后卡不看。把方法 1-3 写成 40-55 字的自成语句（标题 + 一个要点 + 句号），把展开细节下沉到 4-8，卡就不会生硬截断。
2. **API 名/长英文串会毁掉 60 字断点**——把长标识符从方法 1-3 移出，断点立刻干净。
3. **中文引号 vs ASCII 直引号要在写文件前统一**——首版混用，导致 edit 精确匹配失败一次；建议正文一律中文引号。
4. **来源的"具体技术栈"与"协作协议 JSON"要主动舍弃**——前者过窄，后者是 persona 里不该出现的编造 API。
